# 架构与最小运行代码

## 6 个运行模块

| 模块 | 职责 |
| --- | --- |
| `app.py` | Tkinter 主窗口、模式与状态、系统 MP3 录音、文件选择、播放预览、切分与导出 |
| `apple_ui.py` | 主题、图标、圆角卡片、按钮、开关和时间轴等界面控件 |
| `audio_sources.py` | 默认系统 / 麦克风设备解析，独立线程采样，PCM WAV 与大文件 RF64 |
| `audio_processing.py` | FFmpeg 高通、轻度频谱降噪、延迟补偿与限幅过滤器参数 |
| `recording_v2.py` | 录屏会话、分段、暂停计时、音轨对齐、混音、输出命名和素材恢复 |
| `cinematic.py` | 原生鼠标轨迹、点击缩放计划、光标平滑、逐帧画面增强和并行渲染 |

`assets/studio.ico` 用于构建 EXE 图标。运行中的界面图标和控件背景通过 Pillow 动态绘制，不依赖外部图片素材。测试、说明、构建脚本不参与正常启动。

## 数据流

```text
Tkinter 主线程：用户操作 → 状态更新 → 轮询事件队列
                                      ↑
录音工作线程：WASAPI loopback → PCM / MP3 编码 → MP3

录屏工作线程：FFmpeg gdigrab → 暂停分段 → 视频拼接
              WASAPI 独立音源 → WAV → 时长对齐 → 混音
              鼠标采集 → 轨迹 / 点击 → 镜头计划 → 效果画面
                                               ↓
                                      H.264 / AAC MP4
```

Python 使用子进程调用外部 FFmpeg。界面线程通过队列接收开始、处理进度、成功与错误，避免编码工作直接阻塞 Tkinter 事件循环。

## 生命周期

主界面按空闲、录制、暂停、停止和处理等状态管理按钮。暂停不计入输出时间轴；每段音频按实际视频时长修正，开始 / 恢复时重新对齐。超过 4 GiB 的原始 WAV 自动切换 RF64 头，支持长会话。

输出使用独占创建和同名编号，尽量避免覆盖已有文件。正常完成后清理本次隐藏会话目录；失败时保留中间文件和日志。硬件初始化仍可能引入少量音画误差。

## 整理范围

本仓库以原项目 `v2` 的 2026-11-10 版本为基线。保留其功能和 6 模块结构，只调整独立目录所需的 FFmpeg 查找路径、测试路径、过时断言和可选桌面测试开关，并补齐环境、构建、文档和发布资料。

没有迁入旧版 `app.py`、旧 EXE、历史快照、PyInstaller 缓存、绝对路径基线散列或以往的录制测试素材。原项目文件保留在原位置。
